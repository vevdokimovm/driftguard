# DriftGuard

Проект по «Разработке приложений на Python» (МИСИС, осень 2026), Евдокимов В. М., МИВТ-26-5-2.

Контроль дрейфа конфигурации серверов. Дрейф — это когда машина тихо расходится с тем, как её настроили:
кто-то поправил конфиг руками, поменял права, поднял лишний порт, обновил пакет. На каждой машине работает агент,
он раз в несколько секунд снимает конфигурацию и отправляет её на сервер. Сервер хранит эталон каждой машины,
сравнивает с ним каждый новый снимок и пишет в журнал, когда появился дрейф и когда ушёл. Клиент на Tkinter
показывает машины, их состояние и что именно разошлось; кнопкой «Принять как эталон» изменения признаются правильными.

## Что входит в снимок

- **файлы** — sha256 содержимого, права и владелец каждого файла из списка (каталоги обходятся рекурсивно);
- **пакеты** — имена и версии из `dpkg`;
- **порты** — слушающие TCP-порты из `/proc/net/tcp` и `tcp6`.

Агент ничего не сравнивает, вся логика на сервере. Одинаковые снимки подряд не сохраняются: у каждого снимка есть
отпечаток (sha256 канонического JSON), и если он совпал с предыдущим, у хоста только обновляется время последнего снимка.

Состояния хоста: `OK` — совпадает с эталоном, `DRIFT` — есть расхождения, `NO_BASELINE` — эталон ещё не принят,
`STALE` — агент давно не присылал снимков.

## Как запустить

```bash
cp .env.example .env                  # вписать POSTGRES_PASSWORD; токены по желанию
docker compose up -d --build --wait   # база, сервер на :8000 и две «машины» с агентами (node-a, node-b)
python client/driftguard_client.py    # клиент, можно указать --server URL и --token TOKEN
```

Устроить дрейф на машине и вернуть как было:

```bash
docker compose exec node-b drift_scenario.sh apply    # правка конфига, chmod 777, порт 9999, пакет 1.0 → 1.1
docker compose exec node-b drift_scenario.sh revert   # всё назад, сервер отметит возврат к эталону
python demo/smoke.py                                  # весь сценарий целиком с проверками
```

Агент на своей машине (нужен только Python, зависимостей нет):

```bash
python agent/drift_agent.py --server http://SERVER:8000 --watch /etc/ssh/sshd_config --watch /etc/nginx --interval 30
```

## API

- `GET /api/health` — сервер жив (без токена);
- `POST /api/snapshots` — снимок от агента (заголовок `X-Agent-Token`, если задан `AGENT_TOKEN`);
- `GET /api/hosts` — все хосты с состоянием и числом расхождений;
- `GET /api/hosts/{id}/drift` — расхождения последнего снимка с эталоном;
- `POST /api/hosts/{id}/baseline` — принять последний снимок как эталон;
- `GET /api/hosts/{id}/snapshots?limit=N` — история снимков;
- `DELETE /api/hosts/{id}` — удалить хост со снимками и событиями;
- `GET /api/events?limit=N&host_id=ID` — события: дрейф найден, дрейф ушёл, принят эталон;
- `GET /api/audit?limit=N` — журнал действий.

Swagger открывается на http://localhost:8000/docs.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest -q && flake8 --max-line-length=120 server agent client tests demo
```

В CI после тестов стенд поднимается в docker compose и `demo/smoke.py` проверяет весь сценарий на настоящих контейнерах.

Без Docker сервер можно запустить на SQLite:
`cd server && DATABASE_URL=sqlite+aiosqlite:///./driftguard.db uvicorn app.main:app --reload`.

## Про безопасность

Токены агентов и клиента разные: агент может только присылать снимки, а принимать эталон и удалять хосты может только
клиент. Если токены не заданы, API открыт, поэтому без них сервер стоит держать только в доверенной сети.
Первый снимок новой машины по умолчанию сразу становится эталоном (`AUTO_BASELINE=true`); если машине нельзя верить
с самого начала, выключите эту настройку и принимайте эталон вручную.
